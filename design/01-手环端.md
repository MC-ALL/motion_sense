# 01 — 手环端

## 定位

可穿戴设备，佩戴于用户手腕，实时采集运动姿态与生理数据，通过 BLE 上报至器材端。设计要求低功耗、长续航、佩戴无感。

手环在系统中承担纯 **BLE Peripheral** 角色，不直接连接网关——器材端充当 BLE Central，扫描并连接附近手环，将手环数据与器材数据一并通过 WiFi 转发至网关。

---

## 1. 数据获取

### 1.1 传感器数据

手环采集以下数据，100 ms 为基础采样周期：

| 数据类型 | 传感器类型 | 字段 |
|---------|-----------|------|
| 三轴加速度 | 六轴传感器 | `accel_x / y / z`（mg） |
| 三轴角速度 | 六轴传感器 | `gyro_x / y / z`（0.1 °/s） |
| 心率 | 心率传感器 | `heart_rate`（bpm） |
| 步数 | 由加速度推算 | `step_count`（步，本次连接累计） |
| 电量 | ADC 采样 | `battery_pct`（%） |
| 当前绑定器材 | 器材端写入 | `current_equipment_id` |

### 1.2 数据有效性

Payload 中 `data_flags` 字节标注各字段是否有效：

- `bit0 = 1`：姿态数据有效
- `bit1 = 1`：心率数据有效
- `bit2 = 1`：电量低于 10%

传感器未就绪或读数异常时，对应字段填 0 并清除有效位。

### 1.3 采样频率自适应

手环根据运动状态自动调整采样与上报频率：

| 状态 | 条件 | Notify 周期 |
|------|------|------------|
| 运动中 | 加速度变化超阈值 | 100 ms（默认） |
| 静止 | 持续静止超 5 min | 降至 1000 ms |
| 深度休眠 | 持续静止超 10 min | 停止连接，仅周期广播 |

频率也可由云端通过 `config` 下发覆盖，见第 5 节。

---

## 2. 本地告警

手环负责 **P0 生命安全告警**，在本地实时判断，无需经过网关，确保即使 BLE 或 WiFi 中断时保护仍然有效。

### 2.1 告警类型

| 告警码 | 触发条件 | 本地动作 | 上报动作 |
|--------|---------|---------|---------|
| `HR_HIGH` | 心率 > `hr_alert_threshold_high`（默认 180 bpm） | 立即震动 + 蜂鸣 + 显示警告 | MQTT alert（P0/critical，经器材端转发） |
| `HR_LOW` | 心率 < `hr_alert_threshold_low`（默认 40 bpm） | 立即震动 + 蜂鸣 + 显示警告 | MQTT alert（P0/critical，经器材端转发） |
| `FALL_DETECTED` | 加速度突变超跌倒检测阈值 | 立即震动 + 蜂鸣 | MQTT alert（P0/critical，经器材端转发） |
| `BATTERY_LOW` | 电量 < 10% | 屏幕闪烁电量图标 | MQTT alert（P1/warning，经器材端转发） |

### 2.2 处理流程

```
传感器数据采集（100ms）
  │
  ├─ 心率判断 ─→ 超阈值？─→ 是：立即震动/蜂鸣 + 标记 alert 待上报
  │
  ├─ 跌倒检测 ─→ 触发？──→ 是：立即震动/蜂鸣 + 标记 alert 待上报
  │
  └─ 电量检测 ─→ < 10%？─→ 是：屏幕提示 + 标记 alert 待上报
                              │
                              ▼
                         BLE Notify 帧（含 data_flags）→ 器材端 → MQTT alert
```

### 2.3 告警接口

告警通过 WRISTBAND_DATA Notify 上报，`data_flags` 中相应位置位；同时器材端解析后发布 MQTT alert topic。详见 [07-通讯接口定义.md §2.4](./07-通讯接口定义.md)。

## 3. 数据上传

### 3.1 上传方式

手环通过 BLE GATT Notify 将数据上传至器材端，由器材端代为转发至 MQTT Broker。手环无需感知网关或后台的存在。

| 项目 | 规格 |
|------|------|
| 协议 | BLE 5.0 GATT Notify |
| Characteristic | WRISTBAND_DATA（UUID: 0xFFA1） |
| Payload 大小 | 固定 20 bytes（兼容默认 ATT MTU） |
| 字节序 | Little-Endian |
| 默认周期 | 100 ms |

完整 Payload 字节定义见 [07-通讯接口定义.md §1.2](./07-通讯接口定义.md)。

### 3.2 上传内容

每帧 Notify 包含：传感器数据、电量、data_flags、步数，以及当前绑定的器材 ID（`current_equipment_id`，由器材端写入后手环持久保存）。

### 3.3 BLE 连接中断处理

- BLE 连接断开时，手环继续以 100 ms 周期广播，等待器材端重连
- 手环**不缓存**离线期间的数据（无 Flash 缓存需求，数据实时性优先）
- 重连后立即恢复 Notify，器材端负责补填 `ts` 字段

---

## 4. 数据处理

手环本地完成以下轻量计算，减少上报数据量并提升实时性：

| 处理项 | 说明 |
|--------|------|
| 姿态解算 | 由六轴传感器内置 DMP 硬件完成，输出加速度和角速度；手环直接读取并打包，无需 MCU 软解算 |
| 步数统计 | 基于加速度 Z 轴峰值计数，累计本次连接的步数（断连后重置） |
| 心率计算 | 心率传感器 PPG 信号由 MCU 进行峰值检测算法计算，输出 bpm 整数 |
| 跌倒检测 | 检测加速度合向量突变（超阈值），触发 P0 告警 |

复杂运动分析（动作识别、运动建议等）由后台 AI 处理，手环只负责原始数据的采集与本地安全判断。

## 5. 配置持久化与时间同步

### 5.1 时间同步

手环自身无 WiFi，无法直接使用 NTP。时间由器材端在 BLE 连接时写入：

```
器材端上线 → SNTP 同步（经 WiFi）→ 获取 Unix 时间戳
  → BLE 连接手环后
  → 写入 TIME_SYNC Characteristic（UUID: 0xFFA3，4 bytes，uint32 LE）
  → 手环更新本地计时基准
  → 后续 Notify Payload 中 ts 字段携带准确时间
```

若手环尚未同步（刚开机，ts = 0），器材端收到后用本地时间替换再转发 MQTT。

### 5.2 配置持久化

手环需持久化存储以下配置（存入非易失性存储，断电重启后保持有效）：

| 配置项 | 默认值 | 来源 |
|--------|--------|------|
| `hr_alert_threshold_high` | 180 bpm | 云端 config 下发，经器材端 BLE Write 转发 |
| `hr_alert_threshold_low` | 40 bpm | 云端 config 下发，经器材端 BLE Write 转发 |
| `notify_interval_ms` | 100 ms | 云端 config 下发，经器材端 BLE Write 转发 |
| `fall_detect_enabled` | true | 云端 config 下发，经器材端 BLE Write 转发 |
| `current_equipment_id` | 0xFF（未绑定） | 器材端 BLE Write（EQUIPMENT_ID Characteristic） |

配置下发流程：后台 `POST /devices/{id}/config` → 网关拉取待执行命令 → 器材端 MQTT `config` topic → BLE Write → 手环存储。

## 6. 与器材端连接流程

手环作为 BLE Peripheral，被动等待器材端（BLE Central）扫描并发起连接。

### 6.1 连接参数

| 参数 | 值 |
|------|-----|
| 广播间隔 | 100 ms（运动中），1000 ms（深度休眠） |
| 连接间隔 | 100 ms |
| 广播内容 | Manufacturer Specific Data：Device Type=0x01，Device ID，电量 |
| 最大并发连接 | 1（单台器材端连接） |

### 6.2 连接建立步骤

```
1. 手环上电 → 初始化传感器 → 开始 BLE 广播
   广播包携带 Device Type=0x01 和 Device ID（供器材端识别）

2. 器材端扫描到手环广播 → 验证 Device Type 和授权列表
   → 发起 BLE 连接请求

3. 连接建立 → ATT 层 MTU 协商（默认 23 bytes）
   → 器材端执行 GATT Service Discovery，发现 UUID 0xFFA0

4. 器材端写入 CCCD = 0x0001
   → 手环开始每 notify_interval_ms 发送 WRISTBAND_DATA Notify

5. 器材端写入 TIME_SYNC Characteristic（0xFFA3）
   → 手环更新本地时间基准

6. 器材端写入 EQUIPMENT_ID Characteristic（0xFFA4）
   → 手环存储当前器材 ID，后续 Notify 携带 current_equipment_id

7. 正常数据传输阶段
   → 手环持续 Notify → 器材端解析并转发 MQTT
```

### 6.3 断线重连

器材端断开连接后，手环自动恢复广播，等待重连。重连后器材端重复步骤 4–6（时间同步 + 绑定 ID 重写）以确保状态一致。

BLE 断开时，手环将 `current_equipment_id` 重置为 0xFF（未绑定），后续广播帧携带此状态，直到器材端重新连接并写入 EQUIPMENT_ID。

### 6.4 解绑指令处理

器材端检测到空闲超时时，通过 WRISTBAND_CMD 向手环发送解绑指令：

| cmd_type | 含义 | 手环动作 |
|----------|------|---------|
| 0x01 | 震动 | 按 param1 次数震动 |
| 0x02 | 蜂鸣 | 按 param1 × 10 ms 鸣响 |
| 0x03 | 显示文本 | （保留） |
| 0x04 | 解绑 | 清除 current_equipment_id（置 0xFF），停止携带器材 ID |

手环收到解绑指令后，当前绑定状态立即清除，无需断开 BLE 连接，器材端仍可继续接收手环 Notify（此时 `current_equipment_id = 0xFF`）。

### 6.4 GATT Service 摘要

| Characteristic | UUID | Properties | 用途 |
|---------------|------|------------|------|
| WRISTBAND_DATA | 0xFFA1 | Notify | 传感器数据上报（20 bytes，100 ms） |
| WRISTBAND_CMD | 0xFFA2 | Write Without Response | 器材端下发震动/蜂鸣指令 |
| TIME_SYNC | 0xFFA3 | Write | 器材端写入 Unix 时间戳（4 bytes） |
| EQUIPMENT_ID | 0xFFA4 | Write | 器材端写入绑定的器材 ID（8 bytes） |

完整字节定义见 [07-通讯接口定义.md §1.2](./07-通讯接口定义.md)。
