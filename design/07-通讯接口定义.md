# 07 — 通讯接口定义

本文件是 `motion_sense` 当前唯一的接口契约来源，集中约束 BLE、MQTT、REST 与 WebSocket 的稳定边界。

使用原则：
- 新增或修改字段、topic、路径、事件类型时，优先更新本文件。
- `04/05/06/09/10` 负责解释模块设计与交互策略，不重复定义契约。
- 部署、验收、脚本与运行手册不写在本文件中，统一见 `deployment/` 与各模块 `README.md`。

## 1. BLE GATT 契约

说明：BLE 主要面向设备侧实现；当前网关、后台、网页与运维链路不直接参与 BLE 通讯，但仍保留该契约作为嵌入式实现依据。

### 1.1 公共约定

| 项目 | 约定 |
|------|------|
| BLE 版本 | BLE 5.0 |
| 字节序 | Little-Endian |
| 默认 Notify 负载 | 不超过 20 bytes |
| 中心角色 | 器材端 |
| 外设角色 | 手环端 |
| 时间戳 | Unix 秒级整数；器材端负责时间同步 |

### 1.2 手环端 GATT Service

Service UUID：`0xFFA0`

#### `WRISTBAND_DATA` (`0xFFA1`, Notify)

| 字段 | 类型 | 说明 |
|------|------|------|
| `data_flags` | `uint8` | bit 标记：姿态、心率、低电量 |
| `battery_pct` | `uint8` | 电量百分比 |
| `heart_rate` | `uint16` | 心率 bpm |
| `step_count` | `uint16` | 累计步数 |
| `accel_x/y/z` | `int16` | 三轴加速度 |
| `gyro_x/y/z` | `int16` | 三轴角速度 |
| `current_eq_id` | `uint8` | 当前器材编号，`0xFF` 表示未绑定 |
| `reserved` | `uint8` | 保留 |

#### `WRISTBAND_CMD` (`0xFFA2`, Write Without Response)

| 字段 | 类型 | 说明 |
|------|------|------|
| `cmd_type` | `uint8` | `0x01=震动`、`0x02=蜂鸣`、`0x03=显示文本`、`0x04=解绑` |
| `param1` | `uint8` | 命令参数 |
| `param2` | `uint8` | 保留 |
| `checksum` | `uint8` | 异或校验 |

#### `TIME_SYNC` (`0xFFA3`, Write)

| 字段 | 类型 | 说明 |
|------|------|------|
| `unix_ts` | `uint32` | 由器材端写入的 Unix 时间戳 |

#### `EQUIPMENT_ID` (`0xFFA4`, Write)

| 字段 | 类型 | 说明 |
|------|------|------|
| `equipment_id` | `uint8` | 器材编号 |
| `equipment_name` | `char[7]` | ASCII 名称 |

### 1.3 器材端 GATT Service

Service UUID：`0xFFB0`

#### `EQUIPMENT_DATA` (`0xFFB1`, Notify)

| 字段 | 类型 | 说明 |
|------|------|------|
| `equipment_id` | `uint8` | 器材编号 |
| `status` | `uint8` | `0=idle`、`1=active`、`2=fault`、`3=offline` |
| `rep_count` | `uint16` | 当前组累计次数 |
| `power_w` | `uint16` | 当前功率 |
| `energy_wh_x100` | `uint32` | 累计能耗 |
| `axis_angle` | `int16` | 轴位角 |
| `voltage_v_x10` | `uint16` | 供电电压 |
| `current_ma` | `uint16` | 电流 |
| `reserved` | `uint32` | 保留 |

#### `EQUIPMENT_CONFIG` (`0xFFB2`, Write)

| 字段 | 类型 | 说明 |
|------|------|------|
| `config_type` | `uint8` | `0x01=设置目标次数`、`0x02=清零计数`、`0x03=重启` |
| `target_reps` | `uint16` | 目标次数 |
| `reserved` | `uint24` | 保留 |

### 1.4 广播包最小约定

Manufacturer Specific Data：
- `company_id`
- `device_type`：`0x01=手环`、`0x02=器材`
- `device_id`
- `status_byte`

## 2. MQTT 契约

### 2.1 公共约定

| 项目 | 约定 |
|------|------|
| Broker 端口 | `1883` 明文内网，`8883` TLS |
| QoS | 遥测 / 告警 / 配置统一使用 `1` |
| Retained | `status` topic 使用 `retain=true`，其余默认 `false` |
| Payload | UTF-8 JSON |
| 时间字段 | `ts` 表示设备原始时间戳，不得在网关或后台覆盖 |

认证约束：
- 当前开发基线使用 MQTT 用户名 / 密码认证。
- 匿名访问禁用。
- 正式环境必须替换默认口令并收紧 ACL。

时间语义：
- `ts`：设备原始时间戳。
- `gateway_received_ts`：网关收到时间，仅供追踪与排序。
- `backend_received_at`：后台入库时间，仅供追踪与分析。

### 2.2 Topic 命名规范

```text
gym/{gym_id}/{device_type}/{device_id}/{action}
```

其中：
- `device_type`: `wristband | equipment | env | gateway`
- `action`: `telemetry | alert | binding | status | config | ota`

### 2.4 Alert

Topic：`gym/{gym_id}/{device_type}/{device_id}/alert`

```json
{
  "ts": 1712345678,
  "device_id": "wb-001",
  "priority": "P0",
  "level": "critical",
  "code": "HR_HIGH",
  "message": "心率过高",
  "value": 182,
  "threshold": 180
}
```

优先级：
- `P0`：生命安全，设备端本地判断并立即处理。
- `P1`：低风险，由网关边缘处理。

当前告警码：
- `HR_HIGH`
- `HR_LOW`
- `FALL_DETECTED`
- `BATTERY_LOW`
- `EQ_OVERLOAD`
- `CO2_HIGH`
- `PM25_HIGH`
- `TEMP_HIGH`
- `DEVICE_OFFLINE`

### 2.7 Config

Topic：`gym/{gym_id}/{device_type}/{device_id}/config`

命令链路约束：
1. 后台创建配置命令。
2. 在线网关经 `command_ready` 事件收到唤醒。
3. 网关调用 `commands/pending` 拉取命令；长连接异常时继续按轮询兜底。
4. 目标为网关时本地应用；目标为设备时发布到 MQTT `config` topic。
5. 网关调用 `result` 接口回报执行结果。

当前命令状态：
- `pending`
- `succeeded`
- `failed`
- `timed_out`

当前闭环边界：
- 对网关目标：`succeeded` 表示网关已应用配置。
- 对 `wristband/equipment/env`：`succeeded` 仅表示网关已成功发布到局域网 MQTT。
- 设备侧尚未提供 ACK，后台无法确认设备是否真正持久化配置。

配置示例：

```json
{
  "ts": 1712345678,
  "telemetry_interval_s": 30,
  "co2_threshold_ppm": 1000,
  "pm25_threshold_ugm3": 75
}
```

### 2.8 OTA

Topic：`gym/{gym_id}/{device_type}/{device_id}/ota`

当前仅保留契约位置，后台相关 REST 仍为 `501 reserved`。

## 3. REST 契约

Base URL：`/api/v1`

公共约束：
- 业务接口默认要求 `Authorization: Bearer {access_token}`。
- 当前内网免 JWT 接口仅限网关批量入库与命令通道。
- 时间参数使用 ISO 8601。
- 详细字段变化优先向后兼容，新增字段默认可选。

### 3.1 认证

| 方法 | 路径 | 说明 |
|------|------|------|
| POST | `/auth/login` | 登录，返回 access / refresh token |
| POST | `/auth/refresh` | 刷新 access token，refresh token 轮换 |
| POST | `/auth/logout` | 注销 refresh session |

角色：`admin | teacher | student`

### 3.2 用户管理

| 方法 | 路径 | 说明 |
|------|------|------|
| GET | `/users` | 用户列表 |
| POST | `/users` | 创建用户 |
| PATCH | `/users/{username}` | 更新角色、密码、归属范围 |
| DELETE | `/users/{username}` | 删除用户 |

约束：
- `bootstrap admin` 不允许通过业务接口删除或降权。
- `gym_ids`、`device_ids` 是后续范围过滤依据。

### 3.3 设备管理

| 方法 | 路径 | 说明 |
|------|------|------|
| GET | `/devices` | 设备列表 |
| GET | `/devices/{device_id}` | 设备详情 |
| POST | `/devices` | 注册设备 |
| PATCH | `/devices/{device_id}` | 更新设备元数据 |
| DELETE | `/devices/{device_id}` | 删除设备 |
| POST | `/devices/{device_id}/config` | 创建配置命令 |
| POST | `/devices/{device_id}/ota` | OTA 预留，当前 `501` |

设备汇总字段语义：
- `online`：当前连通性布尔值，来自后台对最近一次设备状态的推导；当前规则是 `status` 不为 `offline/disconnected` 时记为 `true`。
- `status`：最近一次业务状态字符串；优先取设备 payload 中的 `status`，否则后台会对绑定事件推导为 `bound/online`，对普通遥测默认推导为 `online`。
- `last_seen_ts`：最近一次进入设备快照的事件时间，取设备 payload 中的 `ts`，单位为 Unix 秒。
- `last_payload`：最近一次写入设备快照的原始 payload；不是统一 schema，会随最近事件类型变化。
- 新注册但尚未上报的设备，当前固定表现为 `online=false`、`status=registered`、`last_seen_ts=null`、`last_payload={}`。

`GET /devices/{device_id}` 示例：

```json
{
  "gym_id": "gym-gz-01",
  "device_type": "equipment",
  "device_id": "eq-020",
  "gateway_id": "gw-020",
  "display_name": "划船机 20",
  "location": "一楼北侧",
  "metadata": {
    "vendor": "acme"
  },
  "status": "online",
  "online": true,
  "last_seen_ts": 1713261600,
  "last_payload": {
    "ts": 1713261600,
    "device_id": "eq-020",
    "gateway_id": "gw-020",
    "power_w": 410.5
  },
  "registered_at": "2026-04-16T10:00:00+00:00",
  "updated_at": "2026-04-16T10:00:00+00:00"
}
```

当前网页端使用到的 `last_payload` 常见字段：
- 手环：`heart_rate`、`step_count`、`battery_pct`、`current_equipment_id`、`relayed_by`
- 器材：`status`、`rep_count`、`power_w`、`energy_wh`
- 环境：`temperature_c` 或 `temperature`、`humidity`、`co2_ppm`、`pm2_5`
- 网关 / 通用状态：`firmware_version`、`ip`

### 3.6 AI 报告

| 方法 | 路径 | 说明 |
|------|------|------|
| POST | `/ai/analyze` | 创建一条 `queued` 报告 |
| GET | `/ai/reports` | 报告列表，支持 `user_id`、`status`、`start`、`end`、`limit`、`offset` |
| GET | `/ai/reports/{report_id}` | 报告详情 |
| POST | `/ai/reports/{report_id}/retry` | 重新生成，产生新的 `queued` 报告 |

状态机：
- `queued`
- `generating`
- `completed`
- `failed`

当前边界：
- 当前已支持真实建单、异步消费、失败重试接口。
- 当前未实现流式正文输出；如后续新增，保持与 `ai_report` 状态事件解耦。

当前详情字段包括：
- `summary_title`
- `summary`
- `insights`
- `recommendations`
- `evidence_session_ids`
- `raw_markdown`
- `error_message`

说明：
- 当前 REST 与 `ai_report` WebSocket 事件都会省略值为 `null` 的字段，因此 `error_message`、`finished_at`、`raw_markdown` 在不同状态下可能不存在。

#### `ops_snapshot`

用途：
- 后台 / 网关的 `/ops/ws` 向 `ops_observer` 推送自观测快照
- `ops_observer` 向网页端 `/api/ws/ops` 推送聚合健康快照

聚合运维快照示例（`/api/ws/ops`）：

```json
{
  "type": "ops_snapshot",
  "data": {
    "items": [
      {
        "module_id": "backend:api-main",
        "module_type": "backend",
        "display_name": "后台主服务",
        "online": true,
        "health_status": "healthy",
        "checked_at": "2026-04-22T10:00:00+00:00",
        "component_total": 4,
        "healthy_components": 4,
        "degraded_components": 0,
        "offline_components": 0,
        "last_error": null
      }
    ],
    "updated_at": "2026-04-22T10:00:00+00:00"
  }
}
```

说明：
- `online` 表示模块当前是否可达。
- `health_status` 表示模块健康度，可能被组件离线、快照过期、最近错误等因素降级。
- `/ops/ws` 当前首包与后续推送的 `data` 是单个模块摘要对象；`/api/ws/ops` 的 `data` 则是 `OpsHealthListResponse` 聚合结果。

### 4.3 客户端消息

业务 WebSocket `/api/ws` 当前支持：
- `ping`
- `subscribe`

运维 WebSocket `/api/ws/ops` 与模块自观测 `/ops/ws` 当前支持：

## 5. 模块通信矩阵

| 来源 | 去向 | 协议 | 当前主用途 |
|------|------|------|-----------|
| 手环 | 器材端 | BLE | 心率 / 姿态 / 绑定器材信息 |
| 器材端 | 网关 Mosquitto | MQTT | 器材遥测、手环中继、绑定、状态 |
| 环境端 | 网关 Mosquitto | MQTT | 环境遥测、告警、状态 |
| 网关 | 后台 | HTTP | 批量入库、命令结果回报 |
| 后台 | 网关 | WS + HTTP | `command_ready` 唤醒 + pending/result 兜底 |
| 后台 | 网页端 | REST + WS | 业务查询与实时事件 |
| 网关 | ops_observer | REST + WS | 自观测健康与统计 |
| 后台 | ops_observer | REST + WS | 自观测健康与统计 |
| ops_observer | 网页端 | REST + WS | 运维健康聚合 |

## 6. 版本记录

- 当前主链路已稳定为：设备 MQTT 上报 -> 网关批量入库 -> 后台实时广播 -> 网页端同源访问。
- 配置命令链路已稳定为：`command_ready` -> `commands/pending` -> `result`，并保留轮询兜底。
- AI 已稳定为：`queued -> generating -> completed/failed`；`ai_chunk` 仅保留契约，不代表已实现。
