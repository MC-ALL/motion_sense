# 09 — 运维观测端

## 文档定位

本文只描述 `ops_observer` 的设计边界、汇聚模型、对外接口与当前限制。

不在本文中展开：
- 起停脚本、验收顺序与运行手册，见 `deployment/compose/README.md`
- 模块单测与部署命令，见 `ops_observer/api_service/README.md`
- 业务接口字段定义，见 [07-通讯接口定义.md](./07-通讯接口定义.md)

## 1. 定位

`ops_observer` 是独立于业务后台的运维观测服务，负责：
- 汇聚网关与后台的健康状态与运行统计
- 持久化运维快照与运维告警
- 向网页端提供统一的运维视图

明确不做：
- 不直连 PostgreSQL、Redis、InfluxDB、Mosquitto 等中间件协议
- 不采集容器 stdout / stderr 日志
- 不维护独立用户体系，直接复用后台 JWT

## 2. 设计边界

当前观测范围只覆盖：
- 网关自观测接口
- 后台自观测接口

通讯方式只使用：
- REST
- WebSocket

因此 `ops_observer` 当前更像“健康与统计聚合器”，而不是全量可观测平台。

## 3. 汇聚模型

### 3.1 上游采集策略

当前采用：
- REST 周期采集为主
- 上游 `WS /ops/ws` 订阅触发即时刷新为辅

采集对象：
- `GET /ops/v1/health`
- `GET /ops/v1/health/components`
- `GET /ops/v1/stats`
- `WS /ops/ws`

当上游 WebSocket 断开时，自动回退到周期采集。

### 3.2 本地持久化

当前使用 SQLite 存储：
- 模块健康快照
- 组件级检查结果
- 运维告警历史
- 最近一次聚合统计结果

选择 SQLite 的原因：
- 部署简单
- 当前写入压力低
- 单容器即可完成落地

### 3.3 运维告警

当前关注的运维事件包括：
- 模块离线
- 模块降级
- 模块恢复
- 连续探测失败
- 指标异常
- 人工关闭与归档

## 4. 对外接口与鉴权

对网页端提供：
- `GET /api/v1/ops/health`
- `GET /api/v1/ops/health/{module_id}`
- `GET /api/v1/ops/alerts`
- `PATCH /api/v1/ops/alerts/{alert_id}/close`
- `GET /api/v1/ops/stats`
- `WS /api/ws/ops`

鉴权边界：
- 当前默认要求后台管理员 JWT。
- `ops_observer` 不单独签发 token，而是复用后台登录态校验。
- 访问上游后台时，可使用部署阶段注入的后台管理员账号自动登录。
- 访问上游网关时，可使用静态 `ops_token`。

## 5. 运行时约束

- 首次启动由默认模板生成正式配置。
- `app_settings.yaml` 变更后需要重启容器。
- SQLite 数据目录固定在共享 runtime 下。
- 全部运行时文件统一落在 `deployment/runtime/`。

## 6. 当前限制

- 当前不采集日志，不做日志检索与关联分析。
- 当前不直接探测数据库或消息中间件协议层，只依赖上游模块自报。
- 当前观测维度仍以健康、统计、状态迁移为主，缺少更细的错误分类与趋势分析。
