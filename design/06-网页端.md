# 06 — 网页端

## 定位

面向健身房管理员、教师和学生的 Web 可视化平台，提供实时数据仪表盘、历史数据查询、告警管理和运维健康视图。业务数据通过后台端获取，基础设施健康视图通过独立运维观测端获取。

---

| 层次 | 选型 |
|------|------|
| 框架 | React 19（hooks） |
| 语言 | TypeScript 5 |
| 构建工具 | Vite |

## 主要页面

### 1. 实时仪表盘

- 所有业务实时数据通过后台 `WS /api/ws` 更新。
- 页面采用“REST 首次加载 + WebSocket 增量更新 + WebSocket 重连后的单次 REST 补同步”，不保留固定低频轮询。
- 页面当前聚焦离线态势、环境均值、能耗汇总与绑定关系，不再承载高频业务时序图。
- 顶部卡片支持展开二级视图，绑定关系卡片支持直接定位到下方绑定视图。

### 2. 器材管理

- 采用“总览页 + 实例详情页”两级结构：`/equipment` 与 `/equipment/{device_id}`。
- 总览页展示自定义器材卡片；实例详情页展示实时功率、累计能耗、绑定手环与历史曲线。

### 3. 手环管理

- 采用“总览页 + 实例详情页”两级结构：`/wristband` 与 `/wristband/{device_id}`。
- 总览页展示自定义手环卡片；实例详情页展示生命体征曲线、绑定状态、绑定历史与配置下发。

### 4. 环境质量

- 采用“总览页 + 实例详情页”两级结构：`/env-quality` 与 `/env-quality/{device_id}`。
- 总览页展示自定义环境节点卡片；实例详情页展示趋势图、超标提示与聚合统计。
- 管理员可在实例详情页同时调整 `telemetry_interval_s`、`co2_threshold_ppm`、`pm25_threshold_ugm3`，不再只支持上报周期。

### 5. AI 分析报告

- 当前已在训练档案页内接入 Phase A 入口：学生档案可直接触发 `POST /api/v1/ai/analyze`。
- 当前训练档案页点击“生成 AI 报告”后，会创建一条真实的 `queued` 报告记录，并给出“打开报告详情 / 查看历史报告”入口。
- 当前已补齐 Phase B 页面骨架：新增 `/ai-reports` 与 `/ai-reports/{report_id}`，并在侧边导航、个人中心与训练档案页接入跳转入口。
- 当前 AI 报告列表页与详情页已直接消费真实报告记录，可查看 `queued / generating / completed / failed` 状态、分析窗口、摘要标题、证据会话、结构化观察结论、建议与失败原因。
- 当前 AI 报告页已改为“首次 REST 加载 + 业务 WebSocket `ai_report` 事件驱动刷新 + WebSocket 重连后的单次 REST 补同步”，便于实时查看状态推进且避免固定低频轮询。
- 当前 AI 报告详情页已支持对 `failed / completed` 报告执行“重新生成 / 再次生成”，前端会创建一条新的 `queued` 报告并自动跳转到新报告详情。
- 当前后台已支持内置规则生成器和 OpenAI 兼容外部模型两条生成路径；前端接口结构保持一致。
- 当前仍未实现流式生成；前端接入草案已单列到 `design/10-AI前端接入草案.md`，后续重点从“自动生成闭环已落地”继续推进到流式输出与更细的交互态。

### 6. 告警管理

- 支持按 `level`、设备、确认状态筛选。
- 支持单条确认与批量确认。

### 7. 用户管理

- 管理员视角的用户、角色、设备管理。
- 已接入后台 `GET/POST/PATCH/DELETE /api/v1/users`，提供管理员用户列表、创建、改角色/密码、删除，以及 `gym_ids` / `device_ids` 归属编辑。
- 已接入后台 `GET/POST/PATCH/DELETE /api/v1/devices`，提供设备注册、元数据维护、所属网关映射与删除。
- 设备管理页当前同时承载“设备清单 / 手环绑定 / 绑定历史”三块管理员能力；注册设备时 `gym_id`、`gateway_id`、`device_id` 已补齐建议选项，减少纯手输。

### 7.1 学生训练档案

- 后台已新增 `GET/POST /api/v1/user-wristband-bindings`、`POST /api/v1/user-wristband-bindings/{id}/unbind`，用于维护学生账号与手环设备的关系。
- 后台已新增 `GET/POST/PATCH /api/v1/workout-sessions` 与 `GET /api/v1/workout-sessions/{session_id}`，用于沉淀训练会话摘要。
- 已接入独立“训练档案”页面，支持 `/training-archive` 与 `/training-archive/{username}`。
- 当前页面会消费 `GET /api/v1/users/{username}/training-profile`，展示当前激活手环绑定、近期训练会话、器材分段和阶段汇总。
- 管理员可从“用户管理”直接跳转到指定用户训练档案；学生默认查看自己的训练档案；管理员 / 教师在训练档案页改为通过选择框切换学生，不再依赖手工输入用户名。
- 学生与手环的绑定 / 解绑写操作已迁移到“设备管理 -> 手环绑定”；训练档案页仅保留当前绑定结果、绑定历史和跳转入口。
- 管理员可在训练档案页直接触发 `POST /api/v1/workout-sessions/aggregate`，对当前查询窗口执行训练会话同步，适合历史数据补算与联调排障。
- 训练会话列表已补齐来源标签、核心指标摘要、会话详情展开与器材分段卡片，便于老师或客户直接查看“什么时间做了什么训练、结果如何”。
- 训练档案页中的提示、空态与跳转说明已统一切换为项目自定义 notice 卡片样式，不再混用旧 `Alert` 视觉。

### 8. 系统健康中心

用于查看网关、后台及其关键组件的在线与健康状态。

页面建议布局：

```text
┌──────────────────────────────────────────────────────────────┐
│ [模块总数] [健康模块] [降级模块] [离线模块]                  │
├──────────────────────────────────────────────────────────────┤
│ gateway/gw-001   healthy   更新时间: 09:00:00               │
│  - gateway_api        healthy   8ms                         │
│  - edge_processor     healthy   4ms                         │
│  - mqtt_broker        healthy   3ms                         │
│  - local_timeseries   degraded  120ms                       │
├──────────────────────────────────────────────────────────────┤
│ backend/api-main offline   更新时间: 08:59:30               │
│  - api_service        offline   timeout                     │
└──────────────────────────────────────────────────────────────┘
```

- 汇总卡片展示健康、降级、离线模块数量。
- 模块列表展示整体状态、最近上报时间、异常组件数。
- 详情展示组件状态、检查时间、延迟、异常详情。
- 当前设计默认优先使用 REST 轮询：
  - `GET /api/v1/ops/health`
  - `GET /api/v1/ops/health/{module_id}`
  - `GET /api/v1/ops/alerts`
  - `PATCH /api/v1/ops/alerts/{id}/close`
  - `GET /api/v1/ops/stats`
- 若需要实时刷新，可接入 `WS /api/ws/ops`。

## 前端语义与文案约束

- 页面级提示与内联反馈统一通过 `NoticeCard`、`PageNotice`、`InlineNotice` 渲染。
- `ui_semantics` 负责集中维护 `NoticeTone`、设备状态徽标与提示语义，不在页面内重复定义颜色和状态口径。
- `message_catalog` 负责集中维护页面提示标题与错误 fallback 文案，页面内优先透传后端原始错误消息，缺失时再回退到目录中的统一文案。
- `device_ui` 负责集中维护设备状态标签、只读标签与命令结果提示，设备详情页不再各自拼装重复 UI 片段。

## 与后台与运维端连接规范

### 业务后台

- REST API：`Authorization: Bearer {jwt}`
- WebSocket：`wss://{host}/api/ws?token={jwt}`
- 断线后指数退避重连（`1s -> 2s -> 4s`，上限 `30s`）
- 未登录时，实时仪表盘、器材总览、手环总览、环境总览、训练档案、AI 报告、告警管理、设备管理与个人中心页仅显示登录提示，不主动请求受保护接口，也不建立业务 WebSocket
- 当前前端已支持：
  - 登录：`POST /api/v1/auth/login`
  - Token 刷新：遇到 `401` 时调用 `POST /api/v1/auth/refresh`
  - 退出：`POST /api/v1/auth/logout`
  - Linux 正式 Compose 默认通过同源路径访问后台：`backend_base_url = ''`、`backend_ws_url = '/api/ws'`
  - 独立登录页：`GET /login`，支持携带来源页面并在登录成功后回跳

### 运维观测端

- REST API：`Authorization: Bearer {jwt}`，复用后台登录得到的管理员 access token
- WebSocket：`wss://{host}/api/ws/ops?token={jwt}`
- 健康中心不直接访问数据库，也不直连网关或后台私有端口。
- Linux 正式 Compose 默认通过网页端同源入口访问运维端：`ops_base_url = ''`、`ops_ws_url = '/api/ws/ops'`。

完整契约见 [07-通讯接口定义.md](./07-通讯接口定义.md)。

- 页面顶部登录态应显示当前角色与有效数据范围。

## 部署

前端构建产物 `dist/` 由 Nginx 静态托管：

- 镜像与默认配置位于 `deployment/web/portal_app/`。
- 模块最小 Compose 样例位于 `deployment/web/compose/docker-compose.yaml`。
- 整栈正式入口位于 `deployment/compose/docker-compose.yaml`。
- Linux 正式部署推荐执行 `sh deployment/compose/start_stack.sh`。
- Compose 辅助脚本位于 `deployment/compose/`，当前已提供 `print_bootstrap_credentials.sh`、`verify_ops_auth_stack.sh`、`verify_system_stack.sh`、`verify_database_stack.sh`、`stop_stack.sh`。
- Linux 正式部署的推荐上线前验收顺序与异常排障顺序，以 `deployment/compose/README.md` 为准；网页端侧重点关注 `runtime_config.js` 首启生成、Nginx 代理、后台登录与“健康中心”展示。
- 统一运行时目录位于 `deployment/runtime/`。
- `runtime_config.js` 由容器入口脚本在网页端容器启动时按当前环境变量重渲染；若需要保留宿主机侧手工修改，可显式设置 `WEB_PORTAL_RUNTIME_CONFIG_MODE=preserve`。
- Linux 正式 Compose 默认由 Nginx 提供单端口同源入口：`/` 对外提供 SPA，`/api/*` 与 `/api/ws` 代理到后台，`/api/v1/ops/*` 与 `/api/ws/ops` 代理到 `ops_observer`。
- 若通过 SSH 远端访问，优先只转发网页端端口 `8080`，不再要求浏览器额外直连 `8000` 与 `8090`。

- `GET /` → React SPA
- `GET /api/*` → 代理至后台业务 API 或运维观测 API
- WebSocket Upgrade 由 Nginx 透传
