# 06 — 网页端

## 文档定位

本文只描述网页端的信息架构、状态模型、权限边界与接入规范。

不在本文中展开：
- 详细接口字段，见 [07-通讯接口定义.md](./07-通讯接口定义.md)
- AI 专项交互演进，见 [10-AI前端接入草案.md](./10-AI%E5%89%8D%E7%AB%AF%E6%8E%A5%E5%85%A5%E8%8D%89%E6%A1%88.md)
- 构建、部署、Nginx 与运行时配置细节，见 `web/portal_app/README.md` 与 `deployment/web/`

## 1. 定位

网页端是业务与运维一体化门户，服务于：
- 管理员
- 教师
- 学生

当前承担：
- 业务数据浏览与实时态势展示
- 设备管理与用户管理入口
- 训练档案与 AI 报告入口
- 运维健康中心入口

## 2. 页面结构

当前主要页面：
- `/login`
- `/`、`/dashboard`
- `/equipment`、`/equipment/{device_id}`
- `/wristband`、`/wristband/{device_id}`
- `/env-quality`、`/env-quality/{device_id}`
- `/alerts`
- `/training-archive`、`/training-archive/{username}`
- `/ai-reports`、`/ai-reports/{report_id}`
- `/device-registry`
- `/user-management`
- `/health-center`
- `/profile`

信息架构原则：
- `/` 作为已登录默认入口，当前直接落到实时仪表盘。
- 总览页负责筛选、概览与跳转。
- 实例详情页负责设备当前状态、历史趋势与配置入口。
- 训练档案页负责学生训练聚合与 AI 发起入口，不再承担绑定写操作。
- 设备管理页承担注册设备、维护学生-手环绑定与查看绑定历史。

## 3. 状态模型与实时策略

### 3.1 当前实时策略

业务页面与 AI 页面当前统一采用：
- 首次 REST 加载
- WebSocket 增量更新
- WebSocket 重连后的单次 REST 补同步

当前不保留固定低频轮询。

### 3.2 当前主要状态域

- 认证状态：登录、刷新、退出
- 业务实时状态：设备快照、告警、绑定、AI 报告状态
- 运维状态：健康快照、运维告警、模块统计
- 页面局部状态：筛选、表单、详情展开、只读提示

### 3.3 AI 页面状态原则

- 训练档案页负责“发起分析 + 快速反馈 + 跳转”。
- 列表页与详情页负责消费 `queued / generating / completed / failed`。
- 当前未实现流式正文展示；如后续实现，仅在详情页消费 `ai_chunk`。

## 4. 权限与数据范围

### 4.1 角色可见性

| 角色 | 可见范围 |
|------|---------|
| `admin` | 全部业务页、管理页、运维页 |
| `teacher` | 业务页、训练档案、AI 报告、个人中心；不可见用户管理、设备管理、系统健康中心 |
| `student` | 业务页、训练档案、AI 报告、个人中心；不可见告警管理、用户管理、设备管理、系统健康中心 |

### 4.2 范围控制原则

- 前端不能只靠本地过滤推断权限，必须以后端返回结果为准。
- 页面顶部和空态提示应明确当前角色与可见范围。
- 教师与学生在设备详情页默认只读，不显示配置下发入口。
- 训练档案页的学生切换入口仅对 `admin` / `teacher` 暴露，且数据范围以后端授权范围为准。

## 5. 与后台和运维端的连接规范

### 5.1 业务后台

- REST：`/api/v1/*`
- WebSocket：`/api/ws?token={jwt}`
- 默认通过同源入口访问，不要求浏览器直接连接后台私有端口

### 5.2 运维观测端

- REST：`/api/v1/ops/*`
- WebSocket：`/api/ws/ops?token={jwt}`
- 同样通过同源入口访问

### 5.3 同源部署原则

当前 Linux 正式部署推荐由网页端 Nginx 提供单端口入口：
- `/` -> SPA
- `/api/*` -> 后台
- `/api/v1/ops/*`、`/api/ws/ops` -> `ops_observer`

这也是远端 Linux + SSH 端口转发的推荐访问方式。

## 6. UI 语义约束

当前约束：
- 页面级提示与内联反馈统一使用项目自定义 notice 样式，不再混用旧 `Alert` 风格。
- 设备状态、只读提示、命令回执、错误 fallback 文案应走统一语义层与文案目录。
- 同一设备状态在仪表盘、设备管理、详情页中保持一致口径，避免出现“两个 offline”这类重复但语义不同的展示。

## 7. 当前限制

- 页面级自动化回归仍不足，当前主要依赖构建验证与整栈联调。
- AI 报告页当前只有非流式完成态展示，没有阶段化进度和正文流式体验。
- 运维健康中心当前展示的是聚合结果，不包含日志视图与基础设施深层诊断。

## 8. 后续计划

- 增加关键页面 smoke test 与 UI 回归。
- 完善 AI 报告页的训练时间线、结构化证据视图与阶段提示。
- 继续优化教师 / 管理员的操作效率，包括选择器、批量操作与页面引导。
