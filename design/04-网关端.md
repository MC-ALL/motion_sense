# 04 — 网关端

## 文档定位

本文只描述网关模块的设计边界、核心链路与当前限制。

不在本文中展开：
- 具体部署脚本与上线步骤，见 `deployment/compose/README.md`
- 模块级测试与构建命令，见 `gateway/edge_processor/README.md`
- 详细字段契约，见 [07-通讯接口定义.md](./07-通讯接口定义.md)

## 1. 职责与边界

网关部署在场馆本地，承担以下职责：
- 接收器材端、环境端通过 MQTT 上报的数据
- 对本地可判定的 P1 告警做边缘判断
- 将 `telemetry / alert / binding / status` 批量转发到后台
- 在后台不可达时做本地缓冲与补发
- 接收后台配置命令并在本地执行或转发到 MQTT
- 对外暴露网关自观测接口，供 `ops_observer` 汇聚

明确不做：
- 不再承担 BLE 接入，BLE 已完全下移到设备侧
- 不直接承担业务后台或网页端的聚合视图职责
- 不在当前阶段确认设备配置是否真正落地，设备侧 ACK 仍未实现

## 2. 数据接入与批量上报

### 2.1 MQTT 输入范围

当前接收以下主题：
- `gym/+/wristband/+/telemetry`
- `gym/+/wristband/+/binding`
- `gym/+/equipment/+/telemetry`
- `gym/+/equipment/+/alert`
- `gym/+/equipment/+/status`
- `gym/+/env/+/telemetry`
- `gym/+/env/+/alert`
- `gym/+/env/+/status`
- `gym/+/gateway/+/config`

字段定义以 [07-通讯接口定义.md](./07-通讯接口定义.md) 为准。

### 2.2 批量上报主链路

当前主链路：
1. `edge_processor` 订阅 MQTT 事件。
2. 新事件先写入本地 InfluxDB 缓冲。
3. 写入后进入“最小聚合窗口 + 阈值触发 + 定时兜底回放”判定。
4. 后台可达时，调用 `POST /api/v1/ingest/batch` 批量上报。
5. 后台不可达时保留本地缓冲，恢复后补发。

当前上传批次统一包含：
- `telemetry`
- `alert`
- `binding`
- `status`

### 2.3 时间语义

- `ts` / `payload.ts`：设备原始时间戳，不得在网关改写。
- `gateway_received_ts`：网关收到时间，用于链路追踪和排序。
- `backend_received_at`：后台入库时间，仅作辅助追踪。

P1 规则判断当前支持：
- `payload_ts`
- `gateway_received_ts`
- `backend_received_at`

默认值仍为 `payload_ts`。

## 3. 边缘规则与告警

### 3.1 当前职责

网关负责 P1 告警判断与联动；P0 告警由手环本地处理，网关只负责转发和记录。

当前 P1 告警包括：
- `EQ_OVERLOAD`
- `CO2_HIGH`
- `PM25_HIGH`
- `TEMP_HIGH`
- `DEVICE_OFFLINE`

### 3.2 热加载方式

规则文件为 `rules.yaml`，支持：
- 后台下发后本地改写并立即触发重载
- 现场直接修改文件后由 `mtime` 检测兜底重载

热加载目标：
- 阈值
- 持续窗口
- 联动动作
- 全局判定时间源

`rules.yaml` 的字段结构与 [07-通讯接口定义.md](./07-通讯接口定义.md) 中的配置契约保持一致。

## 4. 配置命令链路

当前链路：
1. 后台创建设备配置命令。
2. 网关主动保持 `WS /api/v1/gateway/{gateway_id}/commands/ws?token=...`。
3. 收到 `command_ready` 后立即调用 `GET /api/v1/gateway/{gateway_id}/commands/pending`。
4. 若目标是当前网关，则本地更新配置。
5. 若目标是设备，则转发到对应 MQTT `config` topic。
6. 执行结果通过 `POST /api/v1/gateway/{gateway_id}/commands/{command_id}/result` 回报后台。
7. 若长连接异常，仍按 `command_poll_interval_s` 轮询兜底。

当前状态语义：
- 对网关目标，`succeeded` 表示已在网关生效。
- 对设备目标，`succeeded` 仅表示已成功发到 MQTT。

## 5. 运维观测输出

网关对 `ops_observer` 暴露以下接口：
- `GET /healthz`
- `GET /ops/v1/health`
- `GET /ops/v1/health/components`
- `GET /ops/v1/stats`
- `WS /ops/ws`

当前检查对象至少包括：
- `gateway_api`
- `edge_processor`
- `mqtt_broker`
- `local_timeseries_db`
- `backend_api`

默认部署下，`/ops/v1/*` 与 `/ops/ws` 仅供 `ops_observer` 调用，不直接向业务网页端开放。

## 6. 运行时约束

网关模块当前由以下组件构成：
- Mosquitto
- `edge_processor`
- InfluxDB 3 Core

运行时约束：
- 正式配置由默认模板首启生成。
- `rules.yaml`、`logging.yaml` 允许热加载。
- `app_settings.yaml`、Mosquitto 配置、TLS 资产变更需要重启对应容器。
- 全部运行时文件统一落在 `deployment/runtime/`。

## 7. 当前限制

- 设备侧尚未提供 ACK，配置命令无法形成最终闭环。
- MQTT TLS 已预留，但正式证书投放、权限初始化和自动检查仍待补齐。
- `tests/contract/` 与 `tests/integration/` 仍以预留为主，尚未形成稳定自动化回归。

## 8. 后续计划

- 完成 MQTT TLS 生产化校验与宿主机权限初始化脚本。
- 继续增强规则粒度与专项回归覆盖。
- 在设备侧具备 ACK 后再补配置命令真正完成态闭环。
