# 06 — 网页端

## 定位

面向健身房管理员、教师和学生的 Web 可视化平台，提供实时数据仪表盘、历史数据查询、告警管理和 AI 个性化分析报告。通过 WebSocket 接收后台实时推送，通过 REST API 查询历史数据。

---

## 技术栈

| 层次 | 选型 |
|------|------|
| 框架 | React 18（Concurrent Mode，hooks） |
| 语言 | TypeScript 5 |
| 构建工具 | Vite |
| 路由 | React Router v6（懒加载） |
| 状态管理 | Zustand |
| 数据可视化 | Apache ECharts |
| HTTP 客户端 | Axios（拦截器统一处理 JWT） |
| UI 组件库 | Ant Design 5 |
| 实时通讯 | 原生 WebSocket API（封装为自定义 hook） |
| 样式 | Tailwind CSS + Ant Design token |

## 主要页面

### 1. 实时仪表盘

主页，展示健身房全局实时状态：

```
┌─────────────────────────────────────────────────────────────┐
│  [在线设备数]  [当前活跃用户]  [未确认告警数]  [今日总能耗]    │  ← KPI 卡片
├──────────────────────────┬──────────────────────────────────┤
│  环境质量概览             │  活跃手环列表                     │
│  CO₂: 850ppm ✓           │  张三  HR: 142 bpm  步数: 2340   │
│  PM2.5: 18 ✓             │  李四  HR: 165 bpm ⚠            │
│  温度: 26.5°C            │                                  │
├──────────────────────────┼──────────────────────────────────┤
│  器材实时功率             │  环境趋势折线图（近 30 分钟）      │
│  跑步机 A: 580W          │  [CO₂ / 温度 / PM2.5 多线图]     │
│  椭圆机 B: 320W          │                                  │
└──────────────────────────┴──────────────────────────────────┘
```

- 所有数据通过 WebSocket 实时更新，无需刷新
- P0 告警（心率异常、跌倒）以醒目方式弹出通知
- P1 告警（环境/器材异常）显示在告警列表和角标

### 2. 器材管理

- 器材列表（状态：在线 / 使用中 / 离线 / 异常）
- 单台器材详情：实时功率折线图、累计能耗柱状图
- 当前绑定手环（通过 `current_equipment_id` 关联）

### 3. 环境质量

- 各区域环境节点当前数据卡片
- 历史趋势图（时间范围选择：1h / 6h / 24h / 7d）
- 超标记录列表

### 4. AI 分析报告

- 选择用户、时间范围（默认本周）
- 点击「生成报告」→ 后台调用 DeepSeek API
- 报告内容流式逐字显示（WebSocket SSE）
- 报告历史列表，支持导出

### 5. 告警管理

- 告警列表（支持按 priority P0/P1、level、设备筛选）
- 一键确认、批量确认
- 实时新告警 Toast 通知（WebSocket 推送）

### 6. 用户管理（管理员）

- 用户列表、角色分配
- 设备注册与绑定

## 实时数据处理

WebSocket 连接建立后，前端按消息类型分发：

| 消息类型 | 处理方式 |
|---------|---------|
| `telemetry` | 更新对应设备的实时数据 Store |
| `alert` | 写入告警 Store，P0 告警弹出醒目通知 |
| `device_status` | 更新设备在线状态 |
| `ai_chunk` | 追加至报告文本缓冲区，实时渲染 |

实时折线图采用**滑动窗口**方案：前端维护每种指标最近 200 个数据点，超出时移除最旧点，ECharts 以 `animation: false` 保障性能。

---

## 与后台连接规范

- REST API：`Authorization: Bearer {jwt}`，刷新 Token 由 Axios 拦截器自动处理
- WebSocket：`wss://{host}/api/ws?token={jwt}`，断线后指数退避重连（1s → 2s → 4s，上限 30s）
- 重连后通过 REST API 拉取最新设备状态（不依赖 WebSocket 缓存）

完整接口格式见 [07-通讯接口定义.md §3、§4](./07-通讯接口定义.md)。

## 权限与角色

| 角色 | 可访问页面 |
|------|-----------|
| 管理员 | 全部页面，含用户管理、设备注册、配置下发 |
| 教师 | 仪表盘、器材、环境、告警、AI 报告（全体学生） |
| 学生 | 仪表盘（个人数据）、AI 报告（仅自己） |

路由守卫通过 JWT 角色字段实现，前端路由与后台 API 双重鉴权。

---

## 部署

前端构建产物（`dist/`）由 Nginx 静态托管，与后台 API 同域：

- `GET /` → 静态文件（React SPA）
- `GET /api/*` → 代理至后台 FastAPI
- WebSocket Upgrade 由 Nginx 透传
