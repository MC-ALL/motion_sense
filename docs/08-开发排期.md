# 08 — 开发排期（4 人小组）

## 团队构成与阶段分工

项目分三个阶段推进，团队成员随进度转换职责：

| 成员 | 专业方向 | Phase 1（S1–S3） | Phase 2（S4） | Phase 3（S5） |
|------|---------|----------------|--------------|--------------|
| **A** | 嵌入式 | 手环端 | 前端集成 | 部署调试 |
| **B** | 嵌入式 | 器材端 | 前端集成 + AI | 部署调试 |
| **C** | 嵌入式 | 环境端 | 嵌入式测试 | 系统集成测试 |
| **D** | 边缘 / 后台 | 网关端 + 后台端 | AI 集成 + 后台测试 | 系统集成测试 |

> **优先级原则：** 嵌入式三端与边缘/后台并行是关键路径，数据链路打通后 A、B 转入前端与 AI 集成，最后全组收敛到部署与系统测试。

---

## 优先级定义

| 级别 | 含义 |
|------|------|
| **P0** | 关键路径，阻塞其他模块，必须按时完成 |
| **P1** | 核心功能，影响演示和验收 |
| **P2** | 重要功能，在 P1 完成后迭代 |
| **P3** | 增强功能，时间允许则实现 |

---

## 总体里程碑

```
Sprint 1   设备 Bring-up + 基础设施
Sprint 2   核心传感器 + 数据链路打通
Sprint 3   子系统联调 + 嵌入式测试
────────── 里程碑 M1：数据可从设备端流入数据库 ──────────
Sprint 4   前端/AI 集成 + 后台完善
────────── 里程碑 M2：端到端演示可运行 ──────────────────
Sprint 5   全链路测试 + 部署 + 收尾
────────── 里程碑 M3：系统交付 ───────────────────────────
```

## 依赖关系与关键路径

```
[D] Mosquitto + FastAPI 基础 (S1)
        │
        ├──→ [B] 器材端 MQTT 上报 (S2)
        ├──→ [C] 环境端 MQTT 上报 (S2)
        └──→ [D] 后台 HTTP ingest + 入库 (S2)
                          │
        [A] 手环 BLE Notify (S2) ──→ [B] 器材端 BLE Central → MQTT (S2)
                [A] 手环 P0 本地告警 (S3)
                          │
                    数据全部入库 (S2 末)
                          │
              ┌───────────┴────────────┐
    [D] 告警 API + WebSocket (S3)   [A/B/C] 单体测试 (S3)
              │
    ─── 里程碑 M1 ───
              │
    [A/B] 前端开发 (S4) ←── WebSocket 推送
    [B/D] AI 集成 (S4)  ←── 后台 AI API
    [C]   环境端测试与系统联调 (S4)
    [D]   配置云控 API (S4)
              │
    ─── 里程碑 M2 ───
              │
    [A/B] 部署 + E2E (S5)
    [C/D] 压测 + 安全 (S5)
              │
    ─── 里程碑 M3 ───
```

**关键路径：** Mosquitto → 后台入库 → WebSocket 广播 → 前端实时展示（任一环节延误都影响里程碑 M1）
