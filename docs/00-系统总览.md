# 粤动智感 — 系统总览

> 基于 WiFi 与 BLE 的无感体训基座
> 面向健身房场景的运动健康与智能辅助 IoT 平台

---

## 设计理念

“无感”是核心原则。系统在用户运动过程中自动完成感知、传输与分析，尽量不要求用户手动操作。

## 当前迭代范围

当前第 1 迭代的实现重点是：

- `04-网关端`：MQTT 接入、边缘缓存、P1 规则、配置下发闭环、自观测接口。
- `05-后台端`：批量入库、设备/告警/遥测查询、配置命令、JWT 基础认证、自观测接口。
- `06-网页端`：实时仪表盘、器材/手环/环境总览与实例详情、告警管理、健康中心基础版。
- `09-运维观测端`：健康聚合、运维告警、统一 REST / WebSocket 视图。

当前不纳入后续开发计划的内容：

- OTA 仅保留接口位置，不继续实现任务编排与升级流程。
- AI 已完成最小可用基线：训练档案页可创建 `queued` 报告，网页端可查看列表/详情；模型生成与流式输出不作为当前交付范围。

## 当前工作记录（2026-04-21）

- 后台已将 AI 能力从纯占位推进到真实排队基线：`POST /api/v1/ai/analyze` 会创建 `queued` 报告记录，并附带训练窗口内的 `evidence_session_ids`。
- 网页端已接入 AI 报告列表页、详情页与训练档案页发起入口，用户可以查看排队中的报告骨架与关联训练会话。
- 基础设施健康口径已统一：网关与后台仅暴露 `/ops/v1/*` / `/ops/ws` 自观测接口，对外健康中心统一由 `ops_observer` 聚合。

## 当前部署基线

- 统一部署目录位于仓库根 `deployment/`，不再在各模块源码目录旁散落编排文件。
- 全仓库共享单一运行时目录 `deployment/runtime/`，首次启动生成的正式配置均来自镜像内 `default_*` 模板。
- 模块级部署资产拆分为 `deployment/<module>/compose/` 与 `deployment/<module>/container/`。
- 整栈入口拆分为 `deployment/compose/docker-compose.yaml` 与 `deployment/container/*.sh`。
- Linux 正式部署使用 Docker Compose `include` 聚合模块 Compose，需 Compose `2.20.3+`。

## 技术栈总览

| 层级 | 平台 | 运行时 | 主要组件 |
|------|------|--------|---------|
| 手环端 | MCU（低功耗，支持 BLE） | RTOS | 六轴传感器、心率传感器 |
| 器材端 | MCU（支持 BLE + WiFi 双模） | RTOS | 功率传感器、编码器、BLE Central |
| 环境端 | MCU（支持 WiFi） | RTOS | 温湿度、光照、CO₂、颗粒物传感器 |
| 网关端 | Linux 主机（ARM64 或 x86） | Docker | Mosquitto、Python 异步边缘处理服务、InfluxDB 3 Core |
| 后台端 | 云服务器 | Python | FastAPI、PostgreSQL/TimescaleDB、Redis |
| 运维观测端 | 云服务器 / 本地运维节点 | Python | FastAPI、SQLite、REST / WebSocket 聚合 |
| 网页端 | 浏览器 | Node.js（构建） | React 19、TypeScript、自定义 SVG 图表 |

## 通讯协议矩阵

| 链路 | 协议 | 方向 | 说明 |
|------|------|------|------|
| 手环 → 器材 | BLE 5.0（GATT Notify） | 单向上报 | 心率、姿态、步数，100 ms 周期 |
| 器材 → 手环 | BLE 5.0（GATT Write） | 下行 | 时间同步、器材绑定 ID、配置 |
| 器材 / 环境 → 网关 | MQTT over WiFi（QoS 1） | 单向上报 | 遥测、告警、状态、绑定事件 |
| 网关 → 后台 | HTTP/S（Batch API） | 单向上报 | 批量遥测、告警、绑定、状态 |
| 后台 → 网关 | REST（HTTP/S） | 下行 | 配置命令建单、轮询拉取、结果回报 |
| 后台 ↔ 网页 | REST + WebSocket | 双向 | 业务查询、实时数据与告警 |
| 网关 / 后台 ↔ 运维观测端 | REST + WebSocket | 双向 | 健康状态、组件明细、运行统计 |
| 网页 ↔ 运维观测端 | REST + WebSocket | 双向 | 健康中心、运维告警、基础设施统计 |

> 约束：运维观测端不直连 PostgreSQL、Redis、InfluxDB 等数据库协议，只通过网关与后台暴露的 REST / WebSocket 获取观测数据。

## 时间语义约定

- `payload.ts` 或消息体中的 `ts` 表示设备原始时间戳，进入网关后不得改写。
- 网关、后台可追加辅助时间字段，例如 `gateway_received_ts`、`backend_received_at`，用于链路追踪与延迟分析。
- 判定时间源默认使用 `payload_ts`，并预留统一枚举：`payload_ts`、`gateway_received_ts`、`backend_received_at`。

## 分级告警机制

| 级别 | 处理位置 | 典型场景 |
|------|---------|---------|
| **P0 生命安全** | 手环本地立即处理，同时上报 | 心率超阈值、跌倒检测 |
| **P1 低风险** | 网关 Edge Processor 边缘判断 | 器材过载、CO₂ 超标、设备离线 |
