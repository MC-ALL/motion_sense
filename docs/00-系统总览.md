# 粤动智感 — 系统总览

> 基于 WiFi 与 BLE 的无感体训基座
> 面向健身房场景的运动健康与智能辅助 IoT 平台

---

## 设计理念

"无感"是核心原则——系统在用户运动过程中自动完成感知、传输与分析，无需手动操作。

## 技术栈总览

| 层级 | 平台 | 运行时 | 主要组件 |
|------|------|--------|---------|
| 手环端 | MCU（低功耗，支持 BLE） | RTOS | 六轴传感器、心率传感器 |
| 器材端 | MCU（支持 BLE + WiFi 双模） | RTOS | 功率传感器、旋转编码器，BLE Central（聚合手环数据） |
| 环境端 | MCU（支持 WiFi） | RTOS | 温湿度传感器、光照传感器、CO₂传感器、颗粒物传感器 |
| 网关端 | Linux 主机（ARM64 或 x86，无 BLE 依赖） | Docker | Mosquitto、Python 边缘处理服务、本地时序数据库 |
| 后台端 | 云服务器 | Python | FastAPI、PostgreSQL/TimescaleDB、Redis、DeepSeek API |
| 网页端 | 浏览器 | Node.js（构建） | React 18、TypeScript、ECharts |

## 通讯协议矩阵

| 链路 | 协议 | 方向 | 说明 |
|------|------|------|------|
| 手环 → 器材 | BLE 5.0（GATT Notify） | 单向上报 | 心率、姿态、步数，100 ms 周期 |
| 器材 → 手环 | BLE 5.0（GATT Write） | 下行 | 时间同步、器材绑定 ID、配置、震动指令 |
| 器材 → 网关 | MQTT over WiFi（QoS 1） | 单向上报 | 器材数据 + 转发手环数据，500 ms 周期 |
| 环境 → 网关 | MQTT over WiFi（QoS 1） | 单向上报 | 环境数据，30 s 周期 |
| 网关 → 后台 | HTTP/S（Batch API） | 单向上报 | 遥测、告警、绑定、状态批量上推 |
| 后台 → 网关 | REST（HTTP/S） | 下行 | 配置命令队列、网关轮询拉取、执行结果回报 |
| 后台 → 网页 | WebSocket | 双向 | 实时数据推送，告警通知 |
| 网页 → 后台 | REST（HTTP/S） | 双向 | 历史查询，配置管理 |
| 后台 → DeepSeek | HTTPS | 双向 | 个性化分析请求 |

## 主要功能

| 编号 | 功能 | 涉及子系统 |
|------|------|-----------|
| F-01 | 环境质量监测（温湿度、光照、CO₂、PM2.5） | 环境端 → 网关 → 后台 → 网页 |
| F-02 | 运动状态感知（姿态、心率、步数） | 手环端 → 器材端 → 网关 → 后台 |
| F-03 | 器材能耗管理（实时功率、累计用电量） | 器材端 → 网关 → 后台 → 网页 |
| F-04 | 手环-器材动态绑定（手环靠近器材自动关联） | 手环端 ↔ 器材端 → 网关 → 后台 |
| F-05 | P0 本地告警（心率异常、跌倒，手环立即处理） | 手环端 → 器材端 → 网关 → 网页 |
| F-06 | P1 边缘告警（能耗异常、环境超标，网关处理） | 网关 → 后台 → 网页 |
| F-07 | 动态配置（告警阈值、上报周期，云控或本地） | 后台 → 网关 → 设备端 |
| F-08 | 历史数据可视化仪表盘 | 后台 → 网页 |
| F-09 | 个性化运动分析与建议（大模型） | 后台 + DeepSeek → 网页 |
| F-10 | OTA 远程固件升级 | 后台 → 网关 → 设备端 |

---

## 分级告警机制

| 级别 | 处理位置 | 典型场景 |
|------|---------|---------|
| **P0 生命安全** | 手环本地立即处理（震动/蜂鸣），同时上报 | 心率超阈值、跌倒检测 |
| **P1 低风险** | 网关 Edge Processor 边缘判断 | 器材过载、CO₂超标、设备离线 |

P0 告警阈值（心率上下限）由云端通过后台配置命令下发至目标网关，网关再转发 MQTT `config` 到器材端，最终由器材端通过 BLE 写入手环持久化。
