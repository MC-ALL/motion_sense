# 03 — 环境端

## 定位

分布式部署于健身房各区域，采集环境质量数据（温湿度、光照、CO₂、PM2.5/PM10），通过 WiFi/MQTT 上报至网关。每个节点独立工作，无需与其他节点通讯。

---

## 1. 数据获取

### 1.1 采集数据类型

| 数据类型 | 传感器类型 | 字段 | 特殊说明 |
|---------|-----------|------|---------|
| 温度 | 温湿度传感器 | `temperature`（°C） | — |
| 湿度 | 温湿度传感器 | `humidity`（%RH） | — |
| 光照强度 | 光照传感器 | `lux`（lux） | — |
| CO₂浓度 | CO₂传感器 | `co2_ppm`（ppm） | 上电预热 3 min 后数据有效 |
| PM1.0 | 颗粒物传感器 | `pm1_0`（µg/m³） | — |
| PM2.5 | 颗粒物传感器 | `pm2_5`（µg/m³） | — |
| PM10 | 颗粒物传感器 | `pm10`（µg/m³） | — |
| 信号强度 | WiFi | `wifi_rssi`（dBm） | 用于监控节点网络质量 |

### 1.2 采样周期

| 数据类型 | 采样周期 | 说明 |
|---------|---------|------|
| 温湿度 | 30 s | 传感器最小间隔限制，环境变化缓慢 |
| 光照 | 30 s | 变化缓慢，30 s 足够 |
| CO₂ | 30 s | 上电后延迟 3 min 再纳入上报 |
| 颗粒物 | 30 s | 连续采样取滑动平均，减少噪声 |

### 1.3 传感器接口类型

环境端采用以下接口与传感器通信（具体传感器型号由硬件选型决定）：

| 接口 | 用途 |
|------|------|
| 单总线（1-Wire / 类似时序） | 温湿度传感器 |
| I²C | 光照传感器 |
| UART | CO₂传感器、颗粒物传感器 |

## 2. 数据上传

### 2.1 上报方式

环境端通过 WiFi 直连 MQTT Broker，每 30 s 上报一次：

**Topic：** `gym/{gym_id}/env/{node_id}/telemetry`

字段定义见 [07-通讯接口定义.md §2.3](./07-通讯接口定义.md)。

上报周期可由云端通过 `config` 动态调整，见第 3 节。

### 2.2 本地告警上报

节点本地进行阈值判断，超标时立即发布 alert（P1 级别）：

**Topic：** `gym/{gym_id}/env/{node_id}/alert`

| 告警码 | 触发条件 | 级别 |
|--------|---------|------|
| `CO2_HIGH` | CO₂ > 1000 ppm | P1/warning |
| `CO2_CRITICAL` | CO₂ > 1500 ppm | P1/critical |
| `PM25_HIGH` | PM2.5 > 75 µg/m³ | P1/warning |
| `TEMP_HIGH` | 温度 > 35 °C | P1/warning |
| `HUMIDITY_HIGH` | 湿度 > 85 %RH | P1/warning |

告警阈值可通过 `config` 下发动态调整，见第 3 节。字段格式见 [07-通讯接口定义.md §2.4](./07-通讯接口定义.md)。

### 2.3 断线缓存与恢复

WiFi 断线期间，节点将数据缓存至本地 Flash（FIFO 队列）：

- 缓存容量：约 24 h 的数据量（2880 条 × 30 s）
- WiFi 恢复后，批量补发缓存数据
- 每条缓存数据携带原始 `ts` 字段，后台按时间戳入库，不产生数据空洞
- 缓存溢出时丢弃最旧数据，保留最新 24 h

### 2.4 MQTT 订阅

| Topic | 用途 |
|-------|------|
| `gym/{gym_id}/env/{node_id}/config` | 动态配置下发 |
| `gym/{gym_id}/env/{node_id}/ota` | OTA 固件升级触发 |

## 3. 配置持久化

### 3.1 可配置项

环境端需持久化以下配置（断电重启后保持有效）：

| 配置项 | 默认值 | 来源 |
|--------|--------|------|
| `telemetry_interval_s` | 30 s | 云端 config 下发 |
| `co2_threshold_ppm` | 1000 ppm | 云端 config 下发 |
| `pm25_threshold_ugm3` | 75 µg/m³ | 云端 config 下发 |
| `temp_threshold_c` | 35 °C | 云端 config 下发 |
| WiFi SSID / 密码 | 出厂烧录 | 本地配置 |
| `node_id` | 出厂烧录 | 本地配置 |
| `gym_id` | 出厂烧录 | 本地配置 |

配置下发格式见 [07-通讯接口定义.md §2.7](./07-通讯接口定义.md)。

---

## 4. 与网关连接流程

环境端通过 WiFi 连接网关上的 MQTT Broker。

### 4.1 连接步骤

```
1. 上电 → 传感器初始化（CO₂传感器等待预热 3 min）
2. WiFi Station 模式连接路由器
3. SNTP 时间同步（获取准确 ts 用于上报）
4. MQTT 连接 Broker（Client ID = node_id）
5. 订阅 config 和 ota topic
6. 开始周期采集并发布 telemetry
```

### 4.2 掉线重连策略

| 事件 | 处理 |
|------|------|
| WiFi 断线 | 自动重连，指数退避（1 s → 2 s → 4 s，最长 30 s） |
| MQTT 断线 | 自动重连，重连后重新订阅 config / ota topic |
| 断线期间 | 继续本地采集，数据写入 Flash 缓存 |
| 重连成功 | 先补发 Flash 缓存，再恢复周期上报 |
